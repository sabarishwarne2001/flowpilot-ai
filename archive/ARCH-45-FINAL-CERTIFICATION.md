# ARCH-45 — Universal Document Corroborator & Discrepancy Matrix: final certification

**Capability:** `capability.universal_corroborator` (Enterprise only). **Baseline:** 79f6277 ("ARCH-44 DONE"). **Migration:** `arch45_step1_corroboration`, inserted beneath the held contract step (`arch44_step1_table_intelligence → arch45_step1_corroboration → arch40_step3_contract_ai_settings`; one file head). **Release head:** `arch45_step1_corroboration`.

**Verdict: DONE.** `python verify_arch45.py --db --mutate --build --regression` → **80 passed, 0 failed** (17 offline, 12 database, 48 mutations, 2 build, 1 regression). Evidence: `backend/evidence/arch45/verify_arch45.json` (including why each mutation was caught).

## 1. What was built

**Compare 2 to 5 processed documents** — a contract and its amended version, a purchase order, invoice and delivery note, a policy and a claim — and get one ranked list of what disagrees, a matrix of every document's value for every difference, the documents side by side with the evidence outlined, and a PDF report.

| Layer | Reads | Finds |
|---|---|---|
| FIELD | `work_items.extracted_entities`, by concept (total, subtotal, tax, currency, parties, dates, policy number, sum insured, …) | `FIELD_MISMATCH`, `FIELD_MISSING` — money within a tolerance, identifiers compared alphanumerically (`POL/2026/128` vs `POL-2026-000123`), parties by ARCH-42 entity id when both are resolved |
| ENTITY | live ARCH-42 mentions, followed through `merged_into_id` to the root (one recursive CTE) | `ENTITY_MISMATCH` (two records for one role), `ENTITY_MISSING` |
| CLAUSE | clauses segmented from the stored page lines | `CLAUSE_MODIFIED` (value / negation / wording), `CLAUSE_MISSING` |
| TABLE | ARCH-44 line items through `tables.service.load` | `LINE_MISMATCH` (quantity, unit price, amount, description, code), `LINE_MISSING` |
| RULE | ARCH-33 plans evaluated on every document's clauses | `RULE_CONFLICT` (one passes, one fails), `RULE_FAILED` (all fail), `RULE_VALUE` (agree, but 90 days vs 60) |

**Clause alignment.** Segmentation drops running headers and footers (lines that recur in the top/bottom band on most pages), page numbers, the outer margin, "Label: value" lines and ARCH-44 table regions; a numbered line after a line that does not end a sentence is a wrapped continuation ("within thirty / (30) days"), not a new clause; a clause across a page break stays one. Text is canonicalised into typed values (`num:45`, `cur:inr num:1200000`, `pct:1.5`, `date:2026-04-01`, `id:004512`; "forty-five (45)" is one value; "1.5 percent" and "1.5%" read alike). Clauses are encoded with the platform's SentenceTransformer (all-MiniLM-L6-v2) on the ENRICH worker profile — a deterministic hashed lexical encoder where the model cannot load — and the cosine is blended with a stop-word-free token Dice score and value agreement. Pairs are assigned with SciPy's Hungarian solver (`linear_sum_assignment`), neighbouring unmatched paragraphs are absorbed when the joined text fits better (a clause re-typeset as two paragraphs is one clause), and pairwise matches are grouped N-way best edge first with at most one unit per document. A clause is reported missing only between documents that share enough clauses to be comparable (a PO and a delivery note are not compared clause by clause).

**Materiality** = the clause's importance (payment, price, liability, term/notice, coverage, delivery/quantity, governing law, confidentiality, … — from its heading and text) × the kind of change. A changed value or a flipped obligation ("shall" → "shall not", "may") is material; rewording never is (capped at 0.45). Severity: HIGH ≥ 0.75, MEDIUM ≥ 0.5, LOW below. Field, entity, line and rule differences carry their own bases, scaled by the relative size of a numeric change.

**Order independence.** Documents are processed in a canonical order (by id), so the result is identical for every order they are given in.

**Cache and invalidation.** A comparison's key is a fingerprint over the engine version, the encoder, the options, the rule digests and each document's content hash — its text, every stored page (text and block boxes), its extracted values, its ARCH-44 tables (id, revision, rejected) and its live ARCH-42 mentions (canonical root and decision). An identical request is answered from the current run (HTTP 200, no job); anything else is queued (202) as `corroboration.run` on the ENRICH profile. Reprocessing (`post_enrichment.dispatch_in_session`), a table extraction, cell correction, column role or review (`tables.service`), and the nightly sweep mark changed comparisons STALE; the page says which document changed and offers "Compare again". One current answer per document set: a newer one supersedes the older.

**Rules.** The workspace's saved ARCH-33 assertion definitions (the latest version per node) and sentences given with the comparison ("Payment terms must not exceed 30 days") run through ARCH-33's own deterministic evaluators. The `llm` family needs a model call per document, so an ad-hoc sentence that compiles to it is refused with the compiler's reason and a saved one is listed as skipped: nothing is billed.

**Data.** `corroboration_runs` (status, set hash, fingerprint, encoder, options, rules, layer stats, anchors for the viewer, counts; one live run per fingerprint by a partial unique index; CHECKs tie every status to its timestamps), `corroboration_documents` (the ordered members and the content hash each was compared at; position trigger; deleting a document deletes its comparisons), `corroboration_pairs` (per-pair agreement, canonical order CHECK), `discrepancies` (kind, materiality, severity band CHECK, layer/kind CHECK, per-document values, evidence spans validated by trigger against the run's documents, decision). Composite foreign keys to `workspaces (id, organization_id)` and `work_items (id, workspace_id)`; zero column drift between models and migration.

**Wiring.** Seventh review-hub kind `CORROBORATION` (reason `MATERIAL_DISCREPANCY`, hub view v6 = v5 + one arm; hidden without the plan; CONFIRM / DISMISS every open material difference, singly or in bulk). Flow Builder trigger `corroboration.discrepancies` (19 triggers over 20 events; the live conformance matrix is ALL CONFORMANT). ARCH-20 erasure removes every comparison that quotes an erased document. Nightly sweep `flowpilot-sweep corroboration` (re-fingerprint, fail stuck runs, delete abandoned STALE/FAILED runs nobody decided).

**API** (11 routes, each gated on the capability as its second line; reads VIEWER, writes CONTRIBUTOR): list, request (200 cached / 202 queued), detail (with live staleness), refresh, decide, review, export (PDF / CSV / JSON, audited `EXPORTED`), page image (rendered with PDFium, `no-store`), delete, workspace rules, a document's comparisons.

**Console.** Enterprise processing → *Document corroborator* (capability-locked): the list, a new-comparison form (pick and order 2–5 documents, rules one per line, the workspace's rules, the materiality threshold), and the run page — status polling, the stale banner, PDF/CSV/JSON downloads, the pairwise agreement grid, the discrepancy matrix (layer filter, material-only, arrow-key navigation, the odd value out tinted), the selected difference with a word diff against any chosen baseline and the decision bar, and the N-pane viewer: page images fetched with the session (`useAuthorizedBlobUrl`), evidence boxes placed in page proportions, and "pages move together" — turning one pane moves the others to the clause aligned with it (the anchors the engine stored). Work Item details shows the document's comparisons with "Compare with…"; the review hub has a *Comparisons* tab. The plan card lists the corroborator.

**PDF report.** Written with pikepdf and Helvetica's published metrics (no new dependency): documents, summary, agreement between every pair, rules and verdicts, every difference with each document's value and page, a word diff for changed clauses, reviewer decisions; the footer carries the run fingerprint.

## 2. Accuracy (synthetic documents with exact truth)

| Gate | Result |
|---|---|
| G4 golden sets — contract vs amended (9 planted), PO/invoice/GRN (9), policy vs claim (4), two clean pairs | **22/22 found, 22/22 of the material findings are planted** |
| G5 held-out, seeds 201–260 (120 sets: randomised contract amendments and procurement triples) | **769/769 found, precision 769/769** |
| Extra stress run (not a gate), seeds 301–400, 200 sets | 1,208/1,208 found, precision 1,208/1,208 |
| G6 order independence | identical output over all 34 permutations (3 documents: 6, 4 documents: 24, pairs: 2 + 2) |
| G3 alignment | Hungarian total equals the brute-force optimum on 300 random matrices |

The distractors every golden and held-out contract carries — formatting-only edits ("seven (7) days" → "7 days", "1.5%" → "1.5 percent", "INR" → "Rs."), a reworded sentence, two swapped clauses, a clause re-typeset as two paragraphs, different line widths and page breaks, a different running header, upper-case headings, a party name written differently but resolved to the same entity — produce **no** material finding. **These are synthetic documents** (Courier PDFs through the production text-layer reader and ARCH-44's extractor). Accuracy on real contracts, scans, proportional fonts and PaddleOCR segmentation is **unmeasured**; every difference carries its evidence and a reviewer decision for exactly that reason.

## 7. Corrections to the prompt and roadmap

- **"Results cached per document-set hash."** A set hash alone would serve one answer for different options, rules or encoders, and a stale one after reprocessing. The set hash groups runs (supersession); the cache key is the fingerprint described above.
- **"A re-extracted table bumps `extracted_tables.revision`."** It does not: ARCH-44's re-extraction replaces the rows (new ids, revision 1); corrections and column roles bump the revision. The fingerprint hashes table ids, revisions and rejection, so both invalidate.
- **Three tables → four.** `corroboration_documents` holds the ordered members of a run and what each was compared at (needed for the stated order, per-document staleness and cascade on deletion).
- **Three alignment layers → five.** Tables (the prompt's fourth) and rules (how ARCH-33 assertions are reused). The llm assertion family is refused/skipped: running it would make a comparison a billed model call.
- **Roadmap "Alembic after ARCH-42" line** still described ARCH-42's chain; corrected to the ARCH-45 chain.
- **Plan cards never listed ARCH-41–44's capabilities**: `PlanSelector` renders only keys in `PLAN_FEATURE_ORDER`, which ARCH-41–44 labelled but never added. All five are now listed (Business adds four, Enterprise the corroborator).
- `reportlab` is pinned in `requirements.txt` but imported nowhere in the application; the report uses pikepdf. ARCH-44's apply prints "run_arch43.ps1" in its closing hint (cosmetic; left untouched).

## 8. Found and fixed during the build

- **A decimal at the start of a clause read as a clause number** ("1.5 percent per month" lost its value), found by G1; multi-level numbers followed by a lower-case word are now values.
- A document title ending in ")" became a clause; a single-page running header merged into the last clause; "(30) days" at a line start read as clause 30; a lone heading swallowed the numbered clause under it; Limitation of Liability aligned with an inserted Service Credits clause (stop words inflated similarity — removed, and the match floor raised to 0.55); a GST summary row became a line item; a PO and a delivery note reported each other's clauses missing (the comparable-document guard); rewording inside a payment clause scored material (capped); "Label: value" lines became clauses; party aliases differed by surface (ARCH-42 ids now decide); identifier punctuation differed.
- A run could read as stale the moment it finished (a table extraction between request and execution): the run's fingerprint is re-keyed to what was actually compared. Accepting a table's figures (REVIEWED) no longer invalidates comparisons; only rejection does.
- The Helvetica width table missed one code point (regenerated in full: 224 entries each for regular and bold); a reviewed-run CHECK was wrong.
- Two harness bugs: a check that serialised a dict keyed by random UUIDs ("45" inside an id) made D6 fail once in eight runs; D9's comparisons collided with cached ones. Both fixed; the database gates then passed 10 consecutive runs.

## 9. Not run in the sandbox

- `run_arch45.ps1` on Windows (its check, apply, migrate, seed, build and verify steps ran as their Linux equivalents; the `git update-index --chmod=+x` step did not).
- **The real all-MiniLM-L6-v2 weights**: Hugging Face downloads are refused by the sandbox proxy (403) and `sentence-transformers` is not installed there. Every accuracy figure above is from the lexical encoder; the SentenceTransformer code path (encode, round, normalise, fingerprint, fallback) ran with a stand-in model in D9.
- Clicking through the console in a browser: the pages are type-checked, built and linted and their API contracts exercised over HTTP, but no UI interaction was driven.
- Real documents (see §2), and performance at the limits (5 documents × 500 pages; a 3-document procurement comparison computes in well under a second).
- `scripts/verify_arch10_step3.py` / `verify_arch10_step9.py` — not run (never against a database you back up). Pre-existing, reproduced on a clean 79f6277 worktree: `verify_arch38` **A1** (`apply_arch38.py` refuses `preset_service.py`, which ARCH-42 edited). ## 10. Deploying

From the repository root: `.\run_arch45.ps1` (add `-AllowUnpriced` on a development database). It checks, applies, migrates to `arch45_step1_corroboration` (stamping around an already-run contract step), seeds an Enterprise tier version carrying `capability.universal_corroborator` (`--carry-forward` moves live subscriptions), sets the sweep script's executable bit, builds the console and runs the full certification. Workers: `corroboration.run` is on the ENRICH profile (the one that already loads the SentenceTransformer). Rollback: `.\run_arch45.ps1 -Rollback` (code), then `alembic downgrade arch44_step1_table_intelligence` (database: drops the four tables and restores ARCH-44's hub view, review kinds and outbox vocabulary).
