## 1. What was built

**Approved outcomes posted to an ERP exactly once, and only called DONE when the ERP says so.** A workspace registers targets (a format, a transport, an optional ERP preset and an acknowledgement mode), maps FlowPilot's canonical posting objects to each target with a versioned, data-only mapping, and posts. Every posting is one row of a ledger that cannot hold two postings of one object to one target, whatever retries, workers, Flow Builder firings or people do.

| Object | Built from |
|---|---|
| VENDOR_BILL | the invoice with the RECONCILED lines of an APPROVED ARCH-31 three-way match (or the line-item table a person accepted, or a COMPLETE ARCH-43 case's invoice), on the ARCH-42 ROOT vendor record |
| PURCHASE_ORDER | the matched PO |
| GOODS_RECEIPT | the matched receipt |
| JOURNAL_ENTRY | the bill's accrual (expense and tax lines against AP), or an accepted ledger-shaped ARCH-44 table (debit / credit / signed amount) |
| PAYMENT_REFERENCE | the payment of the bill, due on its stated date or its date + the terms' net days, rolled FOLLOWING to a business day on the workspace's default ARCH-46 holiday calendar |

**Canonical objects** (`erp/canonical.py`) carry exact `Decimal`s, reconcile before anything is rendered (line arithmetic, subtotal, tax, total; journals balanced, one side per line) and have a content digest. Header values are read with ARCH-45's typed readers; parties follow `merged_into_id` to the root in one recursive query; every derivation is written into the object's notes.

**Formats and ERP presets** (golden files, every one validated):

| Format / preset | Objects | Validated against |
|---|---|---|
| UBL 2.1 | Invoice, Order, ReceiptAdvice | the OASIS UBL 2.1 XSDs, vendored |
| XLSX | all five | ECMA-376 SpreadsheetML part by part, plus the OPC package (content types, relationship targets) |
| CSV | all five | RFC 4180 (re-parsed), formula neutralisation |
| EDI X12 004010 | 810, 850, 856 (+ 997 acknowledgements read) | the grammar in `formats/x12.py` (element ids, lengths, types, code values, order) and an independent envelope re-parse (ISA width 106, GS/GE and ST/SE counts, control numbers) |
| Tally Prime XML | all five vouchers | FlowPilot's XSD of Tally's documented import structure |
| QuickBooks Online · Zoho Books · Business Central · S/4HANA OData · NetSuite REST · generic REST · generic OData | the objects each API takes (27 JSON goldens) | each preset's own JSON Schema |

48 golden files (format × preset × object) are written deterministically (XLSX zip entries have fixed timestamps; the same outcome gives the same bytes).

**The mapping language `fp-map/1`** (`erp/mapping.py`) is JSON data: field paths, constants, concatenation, coalescing, per-field `required` and `default`, and 20 typed transforms (`date` in token formats, OData `edm_date`, `number`, `minor_units`, `currency`, `lookup` against stored tables, `map`, `upper` `lower` `trim` `digits` `alnum` `negate` `abs`, `truncate`, `pad`, `replace` of a literal, `prefix` / `suffix`, and `multiply` by a plain decimal). Nothing is evaluated: executable-looking keys (`eval`, `exec`, `lambda`…), templates (`{{ }}`, `${ }`, `%(…)s`), dunder paths and unknown transforms or tables are refused with the location that offended. A number written without an explicit `decimals` is money and takes the posting currency's exponent (JPY 0, INR 2, KWD 3); an amount that cannot be written exactly is refused, never rounded. A TAX or AP role line never falls back to a default expense account; a code missing from a lookup table fails the posting naming the line and the field. Mappings are versioned per target and object (one ACTIVE; each posting records the version it used).

**Lookup tables** are flat code tables (`erp_lookup_tables`, CHECKed flat: a nested value is refused). Each target gets its own `<prefix>_vendors`, `_accounts`, `_items` and `_settings` when it is created, and the target page lists only its own.

**Delivery: claim, talk, record.** The worker claims a posting under `FOR UPDATE SKIP LOCKED`, a lease token and a lease expiry, and COMMITS before any network I/O; it records the result only if the lease is still its own. Transports: DOWNLOAD (the file, audited and uncached; DONE when a person confirms the ERP took it, optionally by pasting the ERP's response file), SFTP (paramiko, the target's host key PINNED; atomic upload to a temporary name then rename; the 997, Tally import response or `.ack` file read back) and HTTP through the platform's SSRF-safe client (every URL re-validated at connect time; private, loopback, link-local and metadata addresses refused). Auth modes: none, bearer, basic, API-key header, OAuth2 refresh token (a rotated refresh token is stored at once) and client credentials, SSH password or key. Credentials are Fernet-encrypted under the configured `EMAIL_ENCRYPTION_KEYS`; responses show only a fingerprint and no audit record carries them.

**Exactly once.** The ledger key is UNIQUE(target, object kind, source) and a sha256 idempotency key is UNIQUE too; planning is `INSERT … ON CONFLICT DO NOTHING` then a read. When an answer is lost (a reset after sending, a timeout, an expired lease), the worker PROBES the target for the posting's own document number before anything is re-sent (QuickBooks Online by a `DocNumber` query, Zoho Books by bill / PO / reference number, Business Central by `vendorInvoiceNumber` / `number`, S/4HANA supplier invoices by `SupplierInvoiceIDByInvcgParty`, NetSuite by `tranId` — and it also sends NetSuite's `X-NetSuite-Idempotency-Key` — generic REST/OData by a configured probe path and idempotency header). Where no probe exists — an SFTP importer that took the file while the answer was lost, an S/4HANA purchase order or material document — the posting is UNCERTAIN, for a person to decide; it is never re-sent blind. Retries: 30 s × 2^(n−1) with full jitter in [d/2, d], a one-hour ceiling, never sooner than `Retry-After`, and a bounded number of attempts.

**Acknowledgement.** A posting is DONE only on the target's acknowledgement: a REST/OData response that names the created record with every echoed figure equal (total, tax, currency, lines; a tolerance of the currency's minor unit), an X12 997 accepting our group and set (another group ignored), Tally's import RESPONSE (created count and voucher id), an `.ack` file, or a person's confirmation for downloads. A different echoed total is MISMATCH; a refusal is REJECTED; a duplicate refusal of our own bill is DONE.

**States.** PENDING → SENDING → (RETRYING) → DELIVERED → DONE, or an exception — FAILED, REJECTED, MISMATCH, UNCERTAIN — or CANCELLED. CHECKs make impossible: a queued posting without its frozen rendered bytes, a lease outside SENDING, a retry without a due time, DONE without an acknowledgement, an exception without its exception number.

**Data.** `erp_targets`, `erp_mappings`, `erp_lookup_tables`, `erp_postings` (THE LEDGER), `erp_posting_attempts` (every render, send, probe, acknowledgement and review, secrets scrubbed). Composite FKs `(id, workspace_id)` throughout; deleting a document unlinks its postings; a target with postings cannot be deleted (disable it). Zero column drift between models and migration.

**Wiring.** Job `erp.deliver_posting` on the LIGHT worker profile. The sweep (`scripts/sweep_erp_postings.py`, `flowpilot-sweep erp_postings --apply`, every 10 minutes from `deploy/cron.d/flowpilot-sweepers`) auto-posts outcomes approved AFTER a target's auto-post was switched on, re-enqueues due retries and expired leases, reads SFTP acknowledgements and times out unconfirmed downloads. Exceptions are the review hub's ninth kind (POSTING, reason POSTING_EXCEPTION; RETRY / ACCEPT with the ERP's reference / CANCEL, one at a time or in bulk) and raise the Flow Builder trigger `posting.failed` once per exception (22 triggers over 23 events). The Flow Builder action `erp.post` (eight actions) takes an author-chosen target of its own workspace and the objects that target accepts, never a document-derived parameter, and runs on "Three-way match approved" and "Case completed". ARCH-20 erasure: postings built from a subject's documents lose every quoted value (file, canonical and mapped objects, document number, attempt details), the ledger row stays so nothing can be posted twice, and one not yet sent is cancelled (one mid-send becomes UNCERTAIN).

**API** (27 routes, each gated on the capability as its second line; targets, credentials, mappings and lookup tables ADMIN; posting and decisions CONTRIBUTOR; reads VIEWER): the catalogue (formats, presets, objects, auth modes, transforms), targets (list, create, detail, edit, delete), credential, test connection, mappings (read, save a version, validate, reset to the default), lookup tables (list, create, edit, delete), outcomes ready to post, postings (list, post, preview — which posts nothing — detail, file, retry, accept, cancel, acknowledge) and a document's postings.

**Console.** *ERP posting* in the workspace navigation (capability-locked; the plan card lists it): Postings (the ledger, state chips), Ready to post (approved outcomes with a preview of exactly what would be sent), Targets (new target with format, transport, preset and credential fields per auth mode; test connection; versioned mappings with a validator and a live preview) and Lookup tables. A posting page (the rendered file, the canonical and mapped objects, every attempt, decisions, acknowledging a download with the ERP's response file). An *ERP postings* tab on every document's details; the review hub's *ERP postings* tab with Retry all / Cancel all; the `erp.post` form in Flow Builder.

## 7. Found and fixed during the build

- **The first Windows run (91 passed, 8 failed) found four platform bugs; all are fixed, and each now has a gate that fails on the old code on Linux too** (§11).
- **ERP XML parsing broke ARCH-16's XML confinement.** The wider regression run found `scripts/verify_arch16.py` S1 failing: the UBL, Tally, XLSX and schema code imported lxml directly (ARCH-16 allows XML parsing only in `saml_gateway`, because a default parser can be made to read local files or exhaust memory through entities). Tally responses, `.ack` files and pasted response files are untrusted input. All ERP XML now goes through one hardened module, `formats/xmlsafe.py` (DOCTYPE/ENTITY refused in untrusted input, entities never resolved, no DTD loading, no network, no huge trees; vendored schemas only by path). ARCH-16 S1 was widened with an `ARCH47-S1:` sentinel to allow exactly that module and only while it keeps those settings; N2 and MS43–MS45 gate it. `verify_arch16` passes again (29/29).
- **A planning race on the SECOND unique index.** `INSERT … ON CONFLICT (target, object, source) DO NOTHING` still raised a UniqueViolation when two planners collided on the idempotency key; found only by X1's committed, barrier-synchronised planners (a rolled-back single-session test cannot see it). Now `ON CONFLICT DO NOTHING` with no target, then a read.
- **SQLAlchemy stored Python `None` in JSONB as the JSON literal `null`**, so erasure violated `canonical IS NULL` CHECKs (D13). The columns are `JSONB(none_as_null=True)`.
- **Erasing a posting mid-send** violated the rendered-bytes CHECK: the CHECK now allows an erased SENDING/DELIVERED row, and the claim turns an erased SENDING posting into UNCERTAIN (it may have reached the ERP) and anything else into CANCELLED.
- **Money in the currency's exponent.** Golden and held-out runs found KWD (3 decimals) rounded to 2 in the number transform, the Tally amounts and X12 N2 (TDS01 is N2 — ×100 — whatever the currency, so an inexact amount is now refused rather than rounded), and the acknowledgement tolerance hard-coded at 0.01: all now follow the currency.
- **Items looked up in the accounts table**: NetSuite PO `item.id`, S/4HANA `Material` and Tally stock item names read `accounts`; there is now an `_items` table per target, and Tally's stock item is the line's code or description.
- The CSV journal's AP role wrote a bare code without its lookup; it is now a strict lookup.
- `multiply` accepted an exponent literal (`1e3`); the factor must be a plain decimal.
- **XLSX cells misaligned** when the reader met a row with omitted empty cells; cells are now placed by their column reference, and the OPC package structure (content types, relationship targets) is validated as well as the parts.
- A nested value in a lookup table was stringified instead of refused; the target page listed every workspace table instead of the target's own.
- Harness corrections recorded because they are traps: `NEEDS_REVIEW` (not `PENDING_REVIEW`) is the case status; a 402 gate test must send a valid body (an extra field is a 422 before the gate); the backoff check needs a pinned clock; `audit_logs` is append-only, so the committed concurrency gate patches the audit writer for its own organization and deletes it afterwards; a harness that commits must call `register_all()`.

## 8. Corrections to the prompt and roadmap

- **`ARCH-47-HANDOFF-PROMPT.md` was not in ff82586** (ARCH-46's apply creates it, but it had not been committed). ARCH-47's apply carries ARCH-46's canonical text unchanged, so `apply_arch46.py --check` still reports it as applied.
- **"Reuse `corroboration/normalize.py` for money."** It identifies the currency; the amount is parsed by ARCH-44's `tables.values.parse_number` (Indian, Western and European grouping, an exact `Decimal`). Both are used.
- **"Every target URL goes through the webhook preflight."** It does at registration (`webhook_service._preflight_check_url`), but a preflight alone would allow DNS rebinding between the check and the call; every delivery also goes through the SSRF-safe client, which re-validates the resolved address at connect time.
- **"Golden files validated against their published schemas."** UBL 2.1 and ECMA-376 are published and are vendored (`erp/schemas/SOURCES.md`). ASC X12 licenses its standards and Tally publishes no XSD, so X12 is validated against the 004010 grammar encoded in the repository plus an independent envelope re-parse, and Tally against FlowPilot's own XSD of its documented import structure.
- **GOODS_RECEIPT in UBL is `ReceiptAdvice`**, and the X12 goods receipt is an 856; the prompt named only 810/850/856 by number.
- **"A posting is only DONE when the target says so"** needed a third outcome: when the answer is lost and the target offers no probe (an SFTP importer), the posting is UNCERTAIN — a person decides; nothing is re-sent blind.
- **Lookup tables are per target**, and include items (the prompt named vendors and accounts only).
